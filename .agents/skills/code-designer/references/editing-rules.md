# 嵌入式代码修改规则

修改源码、头文件、工程文件或构建配置前读取本文。项目当前 `AGENTS.md`、`memory/rules.md` 和实际实现优先于本文摘要。

## 修改边界

- 修改前查看 `git status --short`；保留用户已有修改，不回退、不覆盖、不清理无关文件。
- 禁止擅自执行 `git reset --hard`、`git clean` 或会覆盖文件的 checkout。
- 先搜索定义、声明、调用点、配置宏和工程引用，再查看相邻代码风格。
- 只改请求范围内的最少文件，不做无关重构，不刷新无关生成物。
- 实际代码、工程文件和构建配置是最终事实；记忆冲突时先核实实现，再修正文档。

## 架构与模块边界

- 参考 `Desktop/rm/Code/serialleg` 的模块拆分和运行时状态组织，维持 `Task -> Application -> Driver -> HAL` 依赖方向。
- 禁止把 `general_task_include.h` 当万能头文件；公共头只包含对外类型所需基础头，`.c` 只包含实际依赖。
- 模块内嵌套结构访问统一放入私有 `*_internal.h`，宏直达最后一级字段或完整业务语义；不得保留“宏展开后再 `.field`”的半封装。
- 遥控通道、键位、鼠标等基础输入叶子宏集中放入已有 `general_define.h`；控制策略组合宏和模块访问宏只留在所属 `*_internal.h`，不得扩散为公共接口。
- `chassis`、`gimbal`、`shoot` 的完整控制主体及跨周期状态分别收口到唯一可写的 `chassis_runtime_t`、`gimbal_runtime_t`、`shoot_runtime_t` 实例；这是项目重构期间对类型命名通则的明确例外。

## 头文件与类型归属

- 头文件按“基础类型 include、模块依赖 include、数值/配置宏、类型定义、extern、小写字段别名宏、函数声明”顺序组织，不重复包含。
- 字段别名宏必须位于对应 `typedef` 之后，避免宏名污染类型定义。
- 协议帧、接收记录和模块专属类型定义在所属 Driver/Application 的公开头中；Task 头只暴露任务接口及必要依赖。
- 函数内状态留在函数作用域；仅跨调用周期共享的状态进入 runtime。共享状态通过模块内可写实例和外部 `const` 指针暴露。

## C 代码风格

- 公开函数使用带模块前缀的 CamelCase，静态函数和变量使用 snake_case，类型使用 CamelCase 且通常不加 `_t`。
- 物理量名称带单位后缀；阈值、周期、角度、倍率、状态和协议值使用有语义的常量。
- 使用 4 空格，不混用 Tab；遵循项目同行左大括号格式，如 `if(condition){`，控制分支不得省略大括号。
- 条件编译块按所在 C 代码层级缩进；长参数、连续赋值和结构初始化按语义对齐。
- 公开 API 使用 Doxygen `@brief`、`@param`、`@retval`、`@note`。
- 删除无调用变量、僵尸状态、重复宏和无效 extern；长函数按单一职责拆分，公开阶段入口只负责编排。
- 所有任务保留周期统计；修改任务优先级、通知链或共享数据时检查实时性、所有权和并发一致性。

## 通信与状态机

- 通信发送数据先形成同一时刻的局部快照，再从快照编码，避免逐字段读取共享状态造成帧内不一致。
- 优先用结构体归并相关状态，并使用 `UPTRIG`、`DOWNTRIG`、`KEY_UPTRIG`、`KEY_DOWNTRIG` 等边沿宏减少重复判断。
- 修改板间通信时同时核对两端 CAN ID、长度、缩放、字节序、频率和电机 ID 冲突。
- QP 生成状态机以 `.qm` 模型为事实来源；逻辑变化必须同步模型和生成代码。主干状态转换优先通过 SIG 事件投递，RC/PC 直接写入只用于不改变主干流转的次要输入。

## 文件与工程

- 含中文的 UTF-8 文件不得使用 PowerShell 5.1 默认编码改写。
- 根 `.clangd` 不添加板级 `CompilationDatabase` 或 `CompileFlags.Add`。
- 新增或移动 `.c` 文件时，同步 include、Keil IncludePath、工程文件组和对应编译数据库。
- 不修改 Keil 临时文件、clangd 缓存和构建产物。
