# 验证清单

按改动风险选择验证，不得把未运行的检查表述为通过。

## 通用检查

- 仅对本次任务明确传入的路径运行 `git diff --check`，审阅对应 diff，并重新搜索旧符号和遗漏调用点。
- 检查声明与定义、条件编译、单位、边界值、空指针、非有限值和数组边界。
- 验证范围只包含本次修改路径；保留用户原有工作区状态，不因无关已有修改而失败。

## 按范围检查

- 控制链：核对 Decision、Estimate、Control 的顺序、通知关系、输入快照和输出节拍。
- 双板通信：核对发送端与接收端的 ID、长度、缩放、字节序、频率和向后兼容性。
- 共用算法/驱动：比较上下板对应实现，说明同步内容和保留差异。
- 新模块或新 `.c`：检查公开声明、初始化入口、Keil 工程收录、IncludePath 和 `compile_commands.json`。
- QP 状态机：同步 `.qm` 模型与生成代码，优先通过 SIG 事件改变主干状态。
- 任务或共享状态：检查优先级、最坏执行时间、竞态、所有权和 `const` 暴露。

## 构建结论

- 可用时构建受影响板的 `.uvprojx`；需要双板同步时构建两板。
- 仅语法检查、文本扫描或 `git diff --check` 不能写成“完整编译通过”。
- 无法运行 Keil、目标硬件或实机测试时，明确列出未验证项和建议验证步骤。
