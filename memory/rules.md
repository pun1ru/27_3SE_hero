# 强制规则

## 修改边界

- 修改前运行 `git status --short`；已有修改属于用户，不得擅自覆盖、回退或清理。
- 禁止擅自使用 `git reset --hard`、`git clean` 等破坏性命令。
- `git checkout --` 前必须说明会覆盖哪些文件并取得用户明确同意。
- 修改紧贴请求范围，不重构无关模块，不刷新无关生成文件。
- 代码和构建配置是事实来源；与记忆冲突时先核实代码，再更新文档。

## 架构与同步

- 遵循 `Task -> Application -> Driver -> HAL` 依赖方向。
- 修改共用算法或驱动时，检查 `hero_down` 与 `hero_up` 是否需要同步，并保留板级差异。
- 修改板间通信时同步检查两端、CAN ID、长度、缩放、字节序和频率。
- CAN ID 不得与现有电机 ID（如 `0x01-0x08`、`0x141`）冲突。
- 修改任务优先级、通知链或共享数据时评估实时性和并发一致性。
- 共享状态使用“模块内可写实例 + 外部 `const` 指针”的所有权模式。

## 编码规范

- 公开函数使用带模块前缀的 CamelCase；静态函数使用小写蛇形。
- 变量和字段使用 snake_case；物理量必须带明确单位后缀。
- 类型使用 CamelCase 且不加 `_t`；数值常量、配置宏和枚举值使用 UPPER_SNAKE_CASE。仅用于缩短结构体叶子字段访问的别名宏使用小写 snake_case，使其在表达式中保持变量式可读性。
- 使用 4 空格和同行左大括号风格：`if(condition){`、`switch(value){`、`void Function(void){`；左大括号紧跟右圆括号且不得换行，右大括号单独一行，关键字与左圆括号之间不留空格。`if`、`else`、`for`、`while` 等控制分支不得省略大括号。
- 条件编译块按所在 C 代码块缩进：`#if`/`#ifdef`/`#elif`/`#else`/`#endif` 与当前语句层级对齐，分支内语句相对指令额外缩进 12 空格，换行参数再缩进 4 空格；不得把函数内预处理指令顶到列首。
- 禁止在控制逻辑中直接使用无语义数字；阈值、周期、角度、倍率、状态值和协议常量必须使用带单位或功能含义的宏、枚举或 `const` 常量。重复出现或会影响行为的数字必须命名；仅数组起始下标、布尔零值等语义完全明确且不会产生歧义的 `0`/`1` 可按上下文保留。
- 连续赋值、条件表达式、函数参数、宏定义和结构初始化必须按语义缩进并纵向对齐；统一使用 4 空格，禁止 Tab 与空格混用。
- API 使用 Doxygen `@brief`、`@param`、`@retval`、`@note` 注释。
- 单位后缀包括 `_deg`/`_d`、`_rad`、`_dps`、`_radps`、`_mps`、`_rps`、`_rpm`、`_nm`。

## serialleg 风格重构规则

- 参考 `Desktop/rm/Code/serialleg` 的模块拆分与运行时状态组织方式。
- 禁止把 `general_task_include.h` 当万能头文件使用；公共头只包含对外类型所必需的基础头，`.c` 只包含实际依赖。
- 模块内部的嵌套结构访问必须通过私有 `*_internal.h` 中直达最后一级字段的简洁宏封装；不得保留“宏展开后再 `.field`”的半封装访问。遥控通道、键位、鼠标字段和重复组合条件也按叶子值或完整业务语义封装；私有宏不得放入公共头或被其他模块依赖。
- 多个模块共同使用的基础输入叶子宏集中放入已有 `general_define.h`；带具体控制策略的组合条件和模块结构访问宏仍归属各自 `*_internal.h`，不得扩散为通用接口。
- `chassis`、`gimbal`、`shoot` 等主要控制模块的完整控制主体和全部跨周期状态分别收口到唯一的 `chassis_runtime_t`、`gimbal_runtime_t`、`shoot_runtime_t` 可写实例中，不得再并列保留独立可写控制实例或函数内静态持久状态。这些显式命名是本项目重构期间对“类型不加 `_t`”通则的例外。
- 头文件依次编排为：基础类型 include、模块依赖 include、数值/配置宏、类型定义、extern、小写字段别名宏、函数声明；不得重复包含。字段别名必须位于对应 `typedef` 之后，避免宏名与结构体成员同名时污染类型定义。
- 函数内状态留在函数作用域；只有跨调用周期共享的模块状态才进入 runtime 结构。
- 通信发送数据先形成同一时刻的局部快照，再从快照编码，避免逐字段读取共享状态造成帧内不一致。
- 优先使用结构体归并相关状态，使用 `UPTRIG`、`DOWNTRIG`、`KEY_UPTRIG`、`KEY_DOWNTRIG` 等简洁边沿宏减少重复判断。
- 删除无调用变量、僵尸状态、重复宏和无效 extern。
- 所有任务保留周期统计；长函数按单一职责继续拆分，公开阶段入口只负责编排。

## 文件与工具

- 新增代码前逐行检查相邻代码的缩进、注释、大括号和命名风格。
- 含中文的 UTF-8 源文件禁止使用 PowerShell 5.1 默认编码读写。
- 根 `.clangd` 禁止添加 `CompilationDatabase` 和 `CompileFlags.Add`。
- 不修改或提交无关的 Keil 临时文件、clangd 缓存和构建产物。
